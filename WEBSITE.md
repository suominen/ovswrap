# Website plan — `https://kimmo.cloud/ovswrap/`

Publish the OVSwrap tracker as a single-page static site, generated by
**Hugo** locally and rsync'd to a personal nginx server (`haig`).  The build
infrastructure mirrors the sibling ghostlock / januscape / cifswitch /
pintheft trackers; only the content and a few config strings differ.

## Architecture

- **Source repo:** `github.com/suominen/ovswrap` (this repo).
- **Generator:** Hugo extended, ≥ 0.146.0.  Run locally; nothing built in
  CI.
- **Source layout:** Hugo project under `site/`.  The tracker is a single
  page at `site/content/_index.md`.
- **Theme:** PaperMod, integrated as a Hugo Module (no submodule).
- **Dev environment:** Nix flake (`flake.nix`) provides hugo + go + git +
  resvg (for `make banner`) + curl/libarchive/zstd (the auto-update agent's
  RPM-unpacking tools).  Auto-activates via `.envrc` if direnv is installed.
- **Build:** `make build` → `hugo --minify --gc --cleanDestinationDir`,
  output in `site/public/`.
- **Publish:** `make dist` → `rsync -avz --delete site/public/` →
  `haig:/ovswrap/`.
- **Web server:** existing nginx vhost on `kimmo.cloud` serves
  `htdocs/ovswrap/` directly at the URL path `/ovswrap/`.

## Naming — nickname slug (CVE assigned)

The bug carries a name (**OVSwrap**) *and* a CVE (**CVE-2026-64531**) from
the outset — the name is the one the researcher's PoC and write-up use.
Following the sibling precedent — which runs both ways (ghostlock,
januscape, pintheft, and cifswitch kept nicknames; Dirty Frag was renamed
to `/CVE-2026-43284/`) — the site uses the **nickname** as its slug
everywhere, with the CVE carried in the tracker body, Summary, and title:

- repo: `~/src/ovswrap`, `github.com/suominen/ovswrap`
- Go module path: `github.com/suominen/ovswrap/site`
- URL: `https://kimmo.cloud/ovswrap/`
- systemd units: `ovswrap-tracker-update.{service,timer}`

No redirect is needed; the slug never moves.

## No companion tracker

OVSwrap is a single, self-contained bug with no twin disclosed alongside
it, so — unlike januscape/ITScape — there is no sibling tracker to
cross-link.  The References table points at the upstream fix, the
introducing commit, the researcher's write-up, and the PoC.

## Tracker content

- One kernel bug, **single verdict axis**: the `3f1f75536668` fix
  (v7.2-rc4) is the only thing that flips a row.  There is no userspace
  reachability gate that ships as its own package (unlike cifswitch's
  cifs-utils second axis).
- The reachability gate — OVS kernel datapath in use, conntrack/FTP-helper
  loaded, unprivileged user namespaces enabled — decides *who* can reach an
  unpatched kernel; it is recorded in prose, **not** as columns, and does
  **not** downgrade a verdict (an affected, unpatched kernel is `:x:`
  whether or not a given host runs OVS or enables userns).
- **Recent regression, so "Not affected" rows exist.**  This is the key
  contrast with ghostlock/januscape (both ~15-year-old bugs where every
  tracked kernel is in-window).  The flaw was introduced by
  `a1e64addf3ff` in **v6.14** (2025-03) and backported into stable only as
  far as 5.15.180 / 6.1.132 / 6.6.84 / 6.12.20 / 6.13.8.  Kernels below
  their series' intro point — EL 4.18 (Rocky 8), EL 5.14 (Rocky 9),
  bullseye's 5.10 default, and any pre-6.14 stream that never took the cap
  removal — are genuinely `:heavy_minus_sign: Not affected — predates the
  introducing commit`, the skeleton status the two current siblings never
  needed.  Each such row is justified against the intro backport point, not
  assumed.
- **Patch status** uses a single **combined table** for upstream and
  distros (`Distribution | Release | Current kernel | First fixed | Fixed
  since | Status`): the upstream kernel is the first `Linux kernel` group;
  opt-in kernels (bullseye `linux-6.1`, PVE opt-in series) are their own
  rows, while the niche EL `kernel-rt` variant stays prose-only; per-distro
  `###` headings are retained only where there is an audience-relevant
  note.  *Current kernel* is live; *First fixed* / *Fixed since* are
  sticky.  In the browser the Distribution column renders as full-width
  group heading rows, and the column header and group headings are sticky.
  This adopts the merged-table layout piloted in ghostlock and folded into
  `~/src/cve-tracker-template`.
- Rows seed `:x:` where a kernel is confirmed in-window and unpatched,
  `:heavy_minus_sign:` where it predates the regression, and
  `:grey_question:` where the EL/Proxmox verdict is pending advisory
  verification.  No unconfirmed "fixed" claims.
- Social/OpenGraph banner — `site/assets/ovswrap-tracker.svg` rasterised
  to `site/static/ovswrap-tracker.png` by `make banner` (resvg), wired
  into the `cover:` front-matter.

## Steps

### 1. Hugo project — scaffolded from januscape

The Hugo skeleton, theme integration, PaperMod overrides, CSS, and i18n
were copied wholesale from the januscape tracker (a current single-table
sibling that already carries subsystem-tree plumbing) on 2026-07-29.  Only
`baseURL`, `title`, the Go module path, the banner, the systemd unit names,
the timer slot, and the rsync destination were retargeted, and the content
+ CLAUDE.md + auto-update prompt were rewritten for this bug.  The
auto-update agent's kernel clone was switched from the KVM tree
(`~/src/linux/kvm`) to the netdev `net` tree (`~/src/linux/net`), where
openvswitch fixes land.

### 2. Publish

- [ ] First `make build` and inspect `site/public/` locally.
- [ ] First `make dist` to push to `haig` — `htdocs/ovswrap/` created
      (let rsync make it).
- [ ] Verify the site renders at `https://kimmo.cloud/ovswrap/`,
      including the RSS feed and OG metadata.

### 3. Automated maintenance

- [ ] `git worktree add -b auto-update ~/src/auto-update/ovswrap main`
- [ ] Install and enable
      `systemd/ovswrap-tracker-update.{service,timer}` as user units
      (see CLAUDE.md for the exact `ln -sr` + `systemctl --user` recipe).
- [ ] Confirm the timer slot `05,17:05` does not collide with the siblings
      (ghostlock `:20`, CVE-2026-42533 `:35`, januscape `:50`).

## Decisions

- **Hosting:** own nginx on `haig`, *not* GitHub Pages.  Same as the
  sibling trackers.
- **URL:** `https://kimmo.cloud/ovswrap/` (nickname slug; see "Naming").
- **Theme integration:** Hugo Modules; theme PaperMod.
- **Canonical source:** `site/content/_index.md`.
- **Recent-regression handling:** a kernel is rated against its series'
  intro backport point, so pre-6.14 streams get `:heavy_minus_sign: Not
  affected` rows rather than `:x:` — the one substantive content departure
  from the ghostlock/januscape seeds.
- **Automated maintenance:** a user-level systemd timer
  (`systemd/ovswrap-tracker-update.timer`, twice daily) runs
  `scripts/auto-update`, which merges `origin/main` into a dedicated
  long-lived `auto-update` branch in a separate worktree and hands off to
  headless Claude with `scripts/auto-update-prompt.txt`.  The agent only
  commits onto `auto-update` — it does not push or open PRs.  Merges of
  `auto-update` into `main` are done manually.  The wrapper prints an
  `OVSwrap tracker auto-update starting …` banner as its first output
  line so aggregated syslog can tell the trackers apart.

## Risks & gotchas

- **Anchor drift.** Hugo/Goldmark's heading slugger differs from GitHub's
  for headings with em dashes, parens, plus signs, or slashes.  Pin brittle
  headings with `### Heading {#stable-id}` if external bookmarks need to
  survive renames.
- **Subpath baseURL.** `baseURL = "https://kimmo.cloud/ovswrap/"` must
  include the trailing slash and the path component.
- **`.cleanDestinationDir`** wipes `site/public/` before each build.
- **rsync `--delete`** removes server-side files not present in the build
  output.  Don't store unrelated content under `htdocs/ovswrap/`.
- **Client-side table tweaks.** `layouts/partials/extend_footer.html`
  rewrites tables in the browser: in the `.distros` table it replaces
  the Distribution column with full-width group heading rows (one per
  distribution; Markdown can't express colspan, so the source keeps a
  plain column); other tables get consecutive duplicate first-column
  cells collapsed via `rowSpan`; status-emoji cells are tagged so
  `custom.css` can hang-indent them.  With JavaScript disabled the
  tweaks are skipped — the table still renders correctly, with the
  Distribution column visible and repeated.

## Social banner

The OpenGraph / social-preview image is generated from an SVG source:
`site/assets/ovswrap-tracker.svg` (1200×630) is rasterised to
`site/static/ovswrap-tracker.png` by `make banner`, which runs `resvg`.
The PNG is committed so ordinary `make build` / `make dist` runs need no
rasteriser.  `resvg` needs the Roboto fonts (`fonts-roboto-unhinted` on
Debian) — without them it silently drops the SVG's sans-serif text.
